# FreeSeek 2.2.1：白屏、诊断和数据导入兼容性

用户反馈：OPPO A11 安装 2.1 后白屏；另一位真我 V30（截图为 RMX3619、Android 12、realme UI 3.0、天玑 700）用户在 2.2.0 中聊天报错且诊断导出失败。两台实机 WebView 版本未知，不能直接将原因归给处理器。

## 复现与修复

在只读 Android 10 / API 29 模拟器、原装 WebView 74.0.3729.185 中安装正式 2.1 APK，界面为空。使用相同 2.1 网页资源的调试验收壳抓到主包 SyntaxError: Unexpected token .，root 无子节点。构建目标此前为 Chrome 105，未转换的可选链等语法无法被旧内核解析。

后续验证还发现 Intl.DisplayNames 在模块初始化时抛出 TypeError；toReversed、toSorted、Object.hasOwn、crypto.randomUUID、Blob.arrayBuffer/text/stream 等在旧内核缺失。逐项修复后才能覆盖启动、聊天及归档完整路径，而非仅消除第一个异常。

隔离测试中移除 toReversed，可同时触发诊断 TypeError 和聊天准备阶段的上传错误，聊天接口调用数为 0。这说明存在与处理器无关、能解释这组症状的兼容性缺陷；尚不能证明真我实机一定只有这个原因。

修复内容：

- 主包、依赖与懒加载包统一转换，入口先加载兼容层，最终 118 个发布 JS 包通过 ES2019 语法检查，静态启动守卫通过 ES5 检查；编译目标与运行时另提供旧内核兼容。
- Blob 流按 256KB 分块回退，不把整个大型备份转换成单个数组；兼容 UUID、媒体查询与尺寸观察，地区名称使用内置中英文表。
- 启动失败提供可见恢复页和原生启动诊断；关于页完整诊断失败后使用原生基础 ZIP，包含环境及原生日志，不含 Key、聊天内容或原始错误消息。基础包与完整包通过 manifest 的模式区分。
- 旧 CSS 的安全区和视口高度提供回退。原有全局弹性缓动的检测建议不属于本次兼容性改动，未作视觉重设计。

## 已完成验证

- 类型检查、lint、4 项 smoke、49 项浏览器回归通过；包括缺失 API 的模拟、启动脚本阻断、恢复页导出、数据导入界面双重确认/取消/损坏包保护及原有上传、长上下文和备份回归。
- Android release 构建与现有原生单测任务通过；生产依赖审计未发现已知漏洞。原生单测仍仅模板用例，不作为机型功能验收证据。
- 真实 WebView 74 引擎：启动、模拟 SSE 聊天、PNG 解码、Mermaid SVG、完整备份导出和导入、诊断 ZIP 生成均通过。
- Android 系统保存器实际保存完整诊断与故障注入后的原生基础诊断；两个 ZIP 均有 6 个可读条目，敏感 canary 未出现；取消基础诊断保存后可重试。
- 数据导入：FreeSeek 备份恢复 4,194,304 字节附件，官方格式 3 历史消息可恢复；损坏 ZIP 和注入 filesStaging 空间不足均拒绝导入并保留原记录。
- 实际系统文件选择器选中 4MB 附件备份，经两次确认后界面显示导入完成，数据库保留 1 个会话、1 个附件及完整原件体积。覆盖安装正式非调试包后导入的记录仍存在，旧内核能够进入应用。
- 最终 APK 检查：应用版本 2.2.1、versionCode 31、minSdk 24、targetSdk 36；正式发布证书与旧版一致。包内无测试 harness 或 api.review.invalid。

临时证据位于 tmp/oppo-review（不入库）：before-errors.json、shared-error-isolation.json、legacy-functional.json、legacy-import-results.json、native-import-ui-results.json、诊断 ZIP、截图和构建日志。当前未拿到两台用户实机，未进行真实付费 API、物理设备长期或全部 WebView 版本验收。
